# Данные команды HackAlem

Эта папка локальная и исключена из Git. Передавайте её внутри команды
отдельно от репозитория; исходные данные не отправляются в OpenAI.

- `scada/turbine_1.csv`, `scada/turbine_2.csv` — побайтовые копии файлов
  организаторов. Проверка и пропуски — `reports/scada_audit.json`.
- `weather/weather_for_ml.csv` — основной файл для участника №1.
  Каждая строка описывает один целевой час одной турбины в одном выпуске.
- `weather/gfs/` — извлечённые точки настоящих GFS, индексы NOAA,
  метаданные исходных файлов и контрольные суммы.
- `weather/bundles/` — проверенные полные погодные выпуски.
- `reports/weather_coverage.json` — фактическое покрытие общей таблицы.
- `reports/backend_verification.json` — итоговая проверка, SHA-256 CSV
  и ограничения сквозного запуска.
- `reports/collection_2025-09-30_2026-02-28.json` — завершённые даты и ошибки сбора.

Начальный диапазон сбора: ежедневные выпуски с 30.09.2025 по 28.02.2026
в 23:00 Казахстана, по 48 часов для двух турбин. Это первоначальный архив
для обучения и проверки, а не вся история SCADA с 2023 года.
Сбор завершён: 152 выпуска, 14 592 строки; повторная проверка без сети пройдена.

В погодной таблице время — ISO UTC (`Z`); для показа используйте `Asia/Almaty`
(+05:00 для этого диапазона). Исходные метки SCADA остаются местными.
Ветер — м/с, температура — °C, направление — градусы «откуда».
Мощность SCADA нормализована в 0–1; это не кВт или МВт.

Ключ погодной таблицы: `(site_id, forecast_origin, target_time)`.
Один целевой час встречается в нескольких выпусках. Нельзя просто удалить
дубли по `target_time`: они относятся к разным моментам прогноза.
Train/validation/test разделяйте по целевым часам без пересечения.
Погоду, доступную после `forecast_origin`, использовать нельзя.

SCADA заканчивается 31.01.2026; фактическая выработка февраля не предоставлена.
До обучения уточните смысл 10-минутной метки (начало/конец интервала).
