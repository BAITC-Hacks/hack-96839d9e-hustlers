# Демонстрация WindOps AI

## Доступный сценарий

Реальные CSV турбин, модели, архив погоды и модули участников 1/2 не предоставлены.
Поэтому сейчас воспроизводится интерфейс и проверки контракта. Это не демонстрация
работающей ML/погодной интеграции. Файл `hackalem_team_prompts.md` отсутствует.

После установки зависимостей по README из корня проекта:

```powershell
.venv\Scripts\python.exe -m streamlit run app.py
```

1. Откройте приложение: demo выключен, прогноз отсутствует, указана причина.
2. Откройте «Проверка качества»: январские метрики отсутствуют. Команды backtest
   пока нет; приложение не обучает модель при просмотре вкладки.
3. Явно включите синтетический режим и загрузите fixture. Проверьте постоянный
   баннер «СИНТЕТИЧЕСКИЕ ДАННЫЕ — ТЕСТ ИНТЕРФЕЙСА» и маркировку графика.
4. Сравните выбранные турбины/горизонт с таблицей и паспортом. Часовой пояс и
   идентификаторы fixture — тестовые, не подтверждённые параметры реальной ВЭС.
5. Измените форму без отправки: отображаемый выпуск должен остаться прежним.
6. Проверьте диагностический CSV и JSON-паспорт. Итоговый экспорт запрещён.
7. Выключите demo: синтетика не должна выглядеть реальным результатом.

Без локальной конфигурации начальная форма предлагает выпуск **31.01.2026 23:00
UTC**, обе тестовые турбины `demo-1`/`demo-2` и 48 часов: целевые часы
**01.02.2026 00:00 — 02.02.2026 23:00 UTC**, 96 строк. Синтетический генератор
находится в `src/windops/ui/fixtures.py`; это единственный включённый образец.
Выбор дат формы 31 января — 28 февраля относится к историческому сценарию,
а не подтверждённому наличию реального архива на каждую дату.

После установки пакетов этот сценарий не требует сети и API-ключей. При отсутствии
сети до установки нужно подготовленное окружение. UI не заменяет архивы погоды
фактической погодой. Настоящий сохранённый артефакт для офлайн-проверки не приложен.

## После подключения backend

Следующие шаги — план приёмки интеграции, не утверждение о её готовности. Точные
реальные даты/артефакты ещё неизвестны; их должен предоставить backend.

1. Январская проверка: независимый backtest, cutoff до проверочных выпусков,
   MAE/RMSE и сравнимые baseline. Нельзя использовать финальную модель, обученную
   на проверяемых январских целевых значениях.
2. Февральский выпуск на 48 часов: реальные `site_id`, согласованные время/зона,
   48 строк на каждую турбину. Фактов февраля нет; ошибка февраля неизвестна.
3. Паспорт: архивный прогноз погоды доступен к историческому выпуску, указаны
   версия, источник, cutoff и проверки. Сегодняшнее скачивание не доказательство.
4. Обновление, если поддерживается: изменившиеся допустимые входы дают новый ID;
   неизменившиеся не создают фиктивную версию. Сравнение только на общих часах.
5. Replay запускается явно и показывает ошибки отдельных выпусков. Полнота
   проверяется по временной сетке, а не только количеству строк.
6. Экспорт: CSV выбранной версии, все версии replay и отдельная таблица февраля
   имеют разные назначения. Правило выбора одного выпуска на час согласовать
   отдельно; официальный формат submission в предоставленном ТЗ не указан.

Произвольный загруженный JSON не становится доверенным от полей `verified`.
Для финального экспорта нужны backend-подтверждение и повторная валидация.
Точка подключения описана в [INTEGRATION.md](INTEGRATION.md).
