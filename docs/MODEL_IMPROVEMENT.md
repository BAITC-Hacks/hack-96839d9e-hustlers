# Улучшение модели с сохранением исходной версии

Дата: 23.09.2026. Проведены два ограниченных эксперимента на CPU, всего
36 конфигураций: 24 варианта параметров и 12 вариантов погодных признаков.
Новые модели geometry v2 прошли заранее заданные условия замены, реальные
backend-проверки и браузер. Исходные модели, январский независимый backtest
и старые февральские прогнозы сохранены без перезаписи.
Новая версия запущена на `http://localhost:8501`; через этот адрес повторно
пройден полный браузерный сценарий. Подключение и результаты зафиксированы
в `data/experiments/ml_weather_geometry_v1/activation.json`.

## Почему проверяем январь

По присланному ТЗ январь — проверка на известных ответах, февраль — основной
прогноз, а 1–2 марта — продолжение последних 48-часовых февральских выпусков.
Для проверки 23 января используется модель с cutoff 31 декабря и погода,
доступная к историческому выпуску. Её ответ сравнивается с уже известной SCADA.
Поэтому ошибка января измерима, а ошибка февраля/марта пока неизвестна.

## Правила эксперимента

До новых обучений записаны неизменяемые протоколы, входные SHA-256, перечень
кандидатов и условия замены. Отдельные файлы результатов также имеют контрольные суммы.

1. Обучение кандидатов: октябрь–ноябрь, cutoff 30.11 22:00 `Asia/Almaty`.
2. Early stopping: только декабрь, доступность ответов до 31.12 22:00;
   явный eval_set, patience=40. Кандидат должен улучшить декабрьский MAE
   минимум на **1%** и не ухудшить MAE/RMSE в целом и в каждом горизонте.
3. На каждую турбину выбирается один кандидат с наименьшим декабрьским MAE.
   Его число деревьев фиксируется до январского сравнения.
4. Новый refit: октябрь–декабрь, без январского eval_set. Для замены требуется
   снижение январского MAE минимум на **2%**, без ухудшения MAE/RMSE в целом
   и отдельно на 1–24/25–48 часах. При отказе следующий кандидат по январю
   не перебирается.
5. При решении о первом февральском выпуске используются только январские ответы
   с `label_available_at <= 31.01.2026 22:00`. Это **1460 пар на турбину**:
   последние два целевых часа января встречаются в двух выпусках и дают четыре
   исключённые пары. Полные 1464 пары остаются диагностикой за весь январь.
6. Программно проверяется сохранность 35 исходных файлов. Артефакты эксперимента
   располагаются вне каталога, который обслуживает исходный plugin по умолчанию.

**Январь уже был просмотрен до этого эксперимента. Новое сравнение не является
независимым тестом.** Это явно записано в паспортах, новом JSON и интерфейсе.
Первоначальная независимая оценка v1 остаётся в `data/ml/january_backtest.json`.
Проверка последнего cutoff добавлена при подготовке подключения: полные январские
метрики не используются как основание исторической доступности новой модели.

## Что проверили

Первая серия: существующие 9/11 признаков, более сильная регуляризация,
MAE/RMSE/Huber, глубины 3–6, максимум 800 деревьев. Лучший выигрыш MAE составил
около 0.52%, ниже порога замены. Улучшение RMSE у некоторых вариантов сопровождалось
ухудшением MAE, поэтому они отклонены. Протокол и результаты:
`data/experiments/ml_guarded_v1/`.

Вторая серия: к существующим признакам добавлены семь величин, вычисляемых
отдельно для каждой погодной строки:

- четыре компоненты единичных векторов ветра на 10/100 м;
- разность скоростей 100 м и 10 м;
- отношение скоростей `v100 / (v10 + 0.5)` с фиксированной защитой нуля;
- скалярное произведение единичных векторов на двух высотах.

Никаких фактических измерений целевого часа и новой погоды не добавлено.
При нулевом ветре единичный вектор принимается равным нулю. Порядок/тип признаков
зафиксирован, версия `gfs-power-geometry-v2`; обучение и predict используют
одну `prepare_features`. В старых наборах `gfs-power-v1` значения не меняются.

Вторая серия: два набора × глубины 3/4/6 на турбину, максимум 600 деревьев,
learning_rate=0.05, MAE, l2_leaf_reg=3, CPU, четыре потока, seed=2026.
Выбраны **depth=6, 88 деревьев** для turbine_1 и **depth=6, 92 дерева** для turbine_2.
Выигрыш декабрьского MAE: **1.12% / 1.48%**.

Функции потерь и параметры сверены с официальными страницами
[CatBoost regression objectives](https://catboost.ai/docs/en/concepts/loss-functions-regression)
и [training parameters](https://catboost.ai/docs/en/references/training-parameters/common).

## Результаты сравнения

Весь январь, по 1464 одинаковые пары на турбину. В ячейках **MAE / RMSE**.
Это разработочное сравнение сохранённых проверочных моделей, не оценка финальных
моделей, обученных на январе.

| Турбина / горизонт | Исходная v1 | Geometry v2 |
| --- | --- | --- |
| turbine_1, весь январь | 0.215566 / 0.299051 | **0.207460 / 0.282933** |
| turbine_1, 1–24 | 0.200758 / 0.278060 | **0.193784 / 0.264308** |
| turbine_1, 25–48 | 0.230868 / 0.319294 | **0.221593 / 0.300970** |
| turbine_2, весь январь | 0.220588 / 0.306425 | **0.211056 / 0.288481** |
| turbine_2, 1–24 | 0.206034 / 0.285758 | **0.195762 / 0.268732** |
| turbine_2, 25–48 | 0.235627 / 0.326410 | **0.226860 / 0.307559** |

Снижение MAE за полный январь: **3.76% / 4.32%**; RMSE: **5.39% / 5.86%**.
На 1460 парах, доступных к финальному cutoff, MAE уменьшился:
**0.215900 → 0.207531 (3.88%)** и **0.220931 → 0.211094 (4.45%)**.
MAE и RMSE также улучшились на обоих горизонтах в этой допустимой выборке.

Это измеренное улучшение средних метрик, не гарантия улучшения каждого часа
или неизвестного февраля. Ошибки всё ещё существенны; ограничение погодной
модели и отсутствие статуса турбин сохраняются. Единица ответа остаётся 0–1.

## Запуск и откат

Из корня, после установки `requirements-dev.txt` и `requirements-ml.txt`:

```bash
bash scripts/run_improved.sh
```

Скрипт запускает существующий Streamlit, выставляя существующие переменные:
Перед запуском `scripts/prepare_improved_runtime.py` создаёт переносимые ссылки
на уже имеющиеся `data/weather/` и `data/scada/` (на Windows без права создания
ссылок копирует каталоги), а при отсутствии конфигурации копирует пример.
Готовые активные, проверочные и финальные модели v2 включены в Git по запросу
передачи финальной версии; остальные экспериментальные веса остаются локальными.

```bash
export PYTHONPATH="$PWD/src"
export WINDOPS_ML_MODULE=windops.ml.plugin
export WINDOPS_EXECUTION_MODE=deterministic
export WINDOPS_OFFLINE=1
export WINDOPS_MODEL_DIR="$PWD/models/geometry_v2/active"
export WINDOPS_DATA_DIR="$PWD/data/experiments/ml_weather_geometry_v1/runtime_data"
.venv/bin/python scripts/prepare_improved_runtime.py
.venv/bin/python -m windops.ml.cli verify-backend
export WINDOPS_SMOKE_BUNDLE="$WINDOPS_DATA_DIR/forecasts/forecast-02326c986e2fb5c389d27361/bundle.json"
export WINDOPS_RUN_REAL_ML_TEST=1
.venv/bin/python -m pytest -q
```

Для отката остановите свой процесс UI и запустите с исходными каталогами:

```bash
PYTHONPATH=src WINDOPS_ML_MODULE=windops.ml.plugin WINDOPS_EXECUTION_MODE=deterministic WINDOPS_OFFLINE=1 WINDOPS_MODEL_DIR="$PWD/models" WINDOPS_DATA_DIR="$PWD/data" .venv/bin/python -m streamlit run app.py
```

## Воспроизведение эксперимента

Исходный ML-код до добавления признаков сохранён в `artifacts/ml_original_source/`.
Он нужен, чтобы проверять исходный зафиксированный выбор без ослабления контроля
SHA кода. В данном checkout повтор стадий использует готовые протоколы и результаты:

```bash
export WINDOPS_DATA_DIR="$PWD/data"
export WINDOPS_MODEL_DIR="$PWD/models"
export PYTHONPATH="$PWD/artifacts/ml_original_source"
.venv/bin/python scripts/improve_model.py select
.venv/bin/python scripts/improve_model.py compare
.venv/bin/python scripts/improve_weather_features.py select
.venv/bin/python scripts/improve_weather_features.py compare
.venv/bin/python scripts/audit_ml.py --report artifacts/original_after_geometry.json

# Текущий код: проверка эквивалентности признаков, gate по cutoff, refit и паспорта.
export PYTHONPATH="$PWD/src"
.venv/bin/python scripts/build_improved_models.py
```

Исходный код ML также есть в существующем пользовательском commit
`169f31186cc82bcc8c95c31c8c94c534b06deca4`. При отсутствии локального снимка
его можно извлечь без изменения рабочей ветки:

```bash
mkdir -p artifacts/ml_reference_checkout
git archive 169f31186cc82bcc8c95c31c8c94c534b06deca4 src/windops | tar -x -C artifacts/ml_reference_checkout
export PYTHONPATH="$PWD/artifacts/ml_reference_checkout/src"
```

Для полного повторного обучения эксперимента нужны отдельная рабочая копия
и пустые каталоги соответствующего эксперимента; сохранённые протоколы не
перезаписываются. Изменение входов, кода или защищённых путей блокирует повтор.
Время запуска не используется для создания новой версии модели.

## Выполненные проверки

**175 passed, без пропусков** с настоящими v2-моделями и smoke bundle.
Проверены совместимость v1/v2, геометрия и нулевой ветер, отсутствие факта
в признаках, сериализация, оба горизонта, перестановка входов, ранний origin,
отказ при ухудшении одной метрики/горизонта, неизменность исходных артефактов.

Настоящий backend дал 58 исходных выпусков, 2784 строки с мартом и 1344 часа
февраля. Повтор не создаёт дублей; обновление сохраняет старую версию и ту же
модель. Прямой BackendAdapter разрешает итоговый экспорт, произвольный JSON — нет.
Chromium проверил новый прогноз, маркировку разработочной оценки, обновление,
replay и совпадение скачанных CSV с сохранёнными. Модели при этом не обучались.

Живой LLM для v2 не проверялся; полученный с обновлениями команды
`data/reports/llm_smoke_verification.json` относится к одному запуску v1.
Факта февраля/марта, номинальной мощности и подтверждения семантики меток/задержки
SCADA по-прежнему нет. Первоначальное улучшение выполнялось без commit/push;
последующий запрос пользователя разрешил объединить обновления и отправить версию.
