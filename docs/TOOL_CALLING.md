# Tool Calling

```text
User
 ↓
LLM
 ↓
Tool Call
 ↓
Validate Arguments
 ↓
Execute Tool
 ↓
Structured Tool Result
 ↓
LLM
 ↓
Final Response
```

## Стандарт

1. Каждый tool имеет уникальное имя в явном реестре разрешённых tools.
2. Каждый tool имеет ясное описание возможностей и ограничений.
3. Каждый tool имеет строгую input schema: типы, обязательные поля, допустимые
   значения/размеры и запрет неизвестных полей, если расширение явно не предусмотрено.
4. Backend валидирует аргументы до выполнения, даже если провайдер обещает schema compliance.
5. Tool не принимает произвольный shell command от LLM и не исполняет сгенерированный код.
6. Tool получает только необходимые permissions; backend проверяет доступ пользователя.
7. Tool возвращает структурированный результат с однозначным статусом.
8. Ошибки структурированы и не скрываются; исключение не превращается в успешный пустой ответ.
9. Там, где это необходимо, логируются имя, call ID, длительность и статус вызова.
   Не логировать secrets и чувствительные аргументы/результаты по умолчанию.
10. Детерминированная логика выполняется обычным кодом, а не LLM.
11. Не создавать tool для каждой мелкой функции.
12. Не создавать tool, если достаточно внутреннего function/service call.

## Абстрактный контракт — только документация

```text
tool:
  name: example_tool
  description: <clear capability and its limits>
  input:
    type: object
    properties:
      ...
    required: [...]
    additionalProperties: false
  output:
    status: success | error
    data: <structured payload on success, null on error>
    error: <null on success, otherwise {code, message, retryable}>
```

Это неполная схема-шаблон, не production tool. Конкретные поля определяются кейсом.
Для ошибки валидации возвращается `status: error` с безопасным сообщением и кодом
`INVALID_ARGUMENTS`; выполнение не начинается. Аналогично различаются неизвестный
tool, отказ доступа, timeout и ошибка выполнения.

Executor сохраняет связь результата с исходным call ID. Orchestrator возвращает
результат модели в формате выбранного провайдера. Stack traces и credentials
модели не передаются. Устанавливаются timeout и лимиты вызовов; повтор действий
с побочными эффектами допускается лишь при контроле идемпотентности/дубликатов.
