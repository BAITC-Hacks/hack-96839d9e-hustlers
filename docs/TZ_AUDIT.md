# Аудит ТЗ участника №1 — 23.09.2026

Это аудит исходной v1. Последующее улучшение с сохранением v1, новыми проверками
и раскрытием статуса января описано в [MODEL_IMPROVEMENT.md](MODEL_IMPROVEMENT.md).
Для повторения исходного аудита используйте сохранённый код, как указано там.

Проверены код, исходные данные, обученные артефакты и настоящий путь до скачивания
CSV из браузера. Найденные расхождения UI исправлены. Конфигурация ML, исходные
CSV, веса моделей, декабрьский выбор и январские результаты сохранены без изменений.
Технический сценарий прошёл проверки; неподтверждённые исходные соглашения и
организационные вопросы перечислены отдельно. Результат хакатона этим не гарантируется.
Отдельная проверка величины ошибок, физических единиц и границ периода:
[MODEL_REVIEW.md](MODEL_REVIEW.md). Она фиксирует существенные январские ошибки
и смещение; корректность реализации не означает высокой точности модели.

## Найдено и исправлено

1. **UI replay не включал первый день февраля.** Поле начиналось с 1 февраля
   и не допускало 31 января. Теперь начальная дата — 31 января, поскольку это
   день выпуска прогноза на 1 февраля. Полный диапазон даёт 58 выпусков.
2. **Месячный экспорт UI использовал другое правило.** Он выбирал последний
   выпуск до целевого часа. Теперь, как и CLI, берёт шаги 1–24 исходного выпуска
   предыдущего местного дня в 23:00. Обновления не подменяют исходные прогнозы.
3. **Адаптер терял связь обновления с предыдущей версией.** Поле
   `revises_forecast_id` сохраняется в объекте UI и паспорте. Выгрузка исключает
   помеченные обновления; неоднозначные исходные версии блокируются.
4. **Месячный CSV мог рассчитываться при ошибках replay.** UI теперь блокирует
   его наряду с полным итоговым CSV. Диагностическая выгрузка остаётся доступна.
5. **Документация демонстрации и сдачи утверждала, что моделей нет.** Она заменена
   фактическим сценарием и проверенным состоянием; поправлен текст пустой вкладки
   качества. `training_cutoff` подписан как граница доступности ответов,
   поскольку это не время последнего целевого часа SCADA.
   В README больше нет утверждения «модель участника 1 ожидается».
6. **Правило игнорирования моделей было удалено.** `models/` восстановлен в
   `.gitignore` для новых артефактов. Уже отслеживаемые командой модели оставлены
   в Git: игнорирование не отменяет ранее сделанное добавление.

Изменения относятся к представлению, отбору выпусков и документации.
Январь не использовался для новой настройки модели. Аудит повторил исходные
декабрьские эксперименты и refit в памяти, сравнил результаты, не публиковал
новые версии и не изменял `src/windops/ml/` или `ml_bridge.py`.

## Повтор аудита

Из корня, после установки зависимостей по [ML.md](ML.md):

```bash
export PYTHONPATH=src
export WINDOPS_ML_MODULE=windops.ml.plugin
export WINDOPS_EXECUTION_MODE=deterministic
export WINDOPS_OFFLINE=1
export WINDOPS_RUN_REAL_ML_TEST=1
export WINDOPS_SMOKE_BUNDLE="$PWD/data/forecasts/forecast-3bd7a5659d75a23ee6b9aea4/bundle.json"
.venv/bin/python scripts/audit_ml.py
.venv/bin/python -m pytest -q --junitxml=artifacts/tz_tests.xml
.venv/bin/python -m compileall -q app.py src tests scripts
.venv/bin/python -m pip check
git diff --check
```

Проверка браузером запускается по [DEMO.md](DEMO.md).
Аудитный скрипт повторяет только уже выбранные эксперименты, без поиска новых
параметров и использования января для выбора; исходный формат CSV проверяется
явно. Числовой допуск независимого пересчёта — 1e-12.

## Что остаётся предположением или требует отдельного действия

- Организаторы ещё не подтвердили начало/конец 10-минутной метки и задержку SCADA.
  Используются разрешённые ТЗ предположения «начало» и 0 минут; они есть в паспортах.
  При изменении семантики понадобятся новые подготовка и оценка с раскрытием
  того, что январь уже был просмотрен.
- Факта февраля нет. Точность внутридневных обновлений не оценена;
  GFS lead при обновлении 7–54 ч против обучающих 19–66 ч. Диагностика это отмечает.
- Живой LLM-вызов не проверялся. Реальный deterministic backend не выдаётся за него.
- Номинальная мощность неизвестна; прогноз не переводится в МВт или МВт·ч.
- Модели, ранее добавленные командой в Git, остаются отслеживаемыми.
  Текущий аудит не удаляет пользовательские файлы и не переписывает историю.
- Официальный формат submission и подтверждение отправки отсутствуют.
  Проверка на отдельном ноутбуке команды и действия сдачи —
  [SUBMISSION_CHECKLIST.md](SUBMISSION_CHECKLIST.md).
